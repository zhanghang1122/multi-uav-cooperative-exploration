# 小论文实验逻辑与评价协议

## 1. 论文必须回答的中心问题

本文不是证明“无人机能够在废墟里飞行”，而是回答：

> 在有界但先验未知的复杂三维废墟环境中，如何通过多无人机在线协同决策，在不使用预设路线、目标点和人工区域划分的条件下，提高自主探索效率和三维地图完整性，同时控制重复探索、飞行代价与安全风险？

论文的完整证据链为：

```text
现实问题
  -> 现有方法局限
  -> 可检验研究问题
  -> 本文方法
  -> 公平对照实验
  -> 量化结果与统计检验
  -> 结论、适用范围和局限
```

用户提出的“目标—行动—结果”应扩展为：

```text
目标：未知废墟的自主探索与三维建图
条件：仅在线局部感知，禁止真值地图和预设路线进入规划器
行动：单机/三机根据在线地图和 Frontier 自主产生视点与轨迹
对照：只改变研究变量，其余环境、传感器和动力学参数保持一致
结果：地图质量、探索效率、安全性、协同性和计算开销
推断：用重复实验和统计检验判断改进是否真实、稳定且有实际意义
```

## 2. 研究问题与假设

### RQ1：单机基线是否成立

在 Ruins-Urban-01 中，官方 FUEL 是否能够只依赖在线局部感知自主终止探索并生成可评价的三维占据地图？

- H1：在固定任务边界内，FUEL 的自主完成率显著高于零，且无预设路线。
- 作用：建立后续三机实验的控制条件，不作为本文创新。

### RQ2：增加无人机是否自然带来有效提升

三架相互独立的无人机是否会因为重复选择相同 Frontier 而浪费资源？

- H2：无协调三机虽然可能缩短部分探索时间，但重复覆盖率、总航程和冲突次数较高。
- 作用：证明“多三架飞机”不等于“集群智能”。

### RQ3：显式协同是否有效

基于 Frontier/动态拓扑任务单元的分配能否让三架无人机探索不同未知分支？

- H3：与无协调三机和最近 Frontier 贪心方法相比，本文方法降低达到同等覆盖率所需的时间、总航程和重复覆盖率。
- H4：本文方法改善三机负载均衡，并保持碰撞安全与实时计算能力。

### RQ4：地图完整性是否同步改善

更好的任务分配是否提高最终三维地图的完整性？

- H5：在相同截止时间下，本文方法具有更高的表面召回率和 F1。
- 注意：若所有方法都运行到无有效 Frontier，最终完整率可能接近，主要差异可能体现在达到同等完整率的时间。不能预先假定本文方法一定提高最终极限完整率。

### RQ5：方法是否具有鲁棒性

在地图种子、通信丢包、定位扰动和单机退出变化时，改进是否仍然存在？

- H6：本文方法在未见随机废墟和受限通信条件下仍保持较高完成率，性能退化可控。

## 3. 对照方法

| 编号 | 方法 | 用途 |
|---|---|---|
| B1 | 单机 FUEL | 验证自主探索和单机建图基线 |
| B2 | 三机独立 FUEL，无任务协调 | 暴露重复探索和资源冲突 |
| B3 | 三机最近 Frontier 贪心分配 | 最小可解释协同基线 |
| B4 | RACER 或等价的区域/任务分配基线 | 与公开多机探索思路比较 |
| M1 | 本文动态 Frontier/拓扑效用协同方法 | 论文主要方法 |
| A1 | M1 去除信息增益项 | 信息增益消融 |
| A2 | M1 去除重复探索惩罚 | 去重机制消融 |
| A3 | M1 去除负载均衡项 | 任务均衡消融 |
| A4 | M1 加入延迟和丢包 | 通信鲁棒性 |
| O1 | 可选强化学习权重/效用预测 | 主体完成后的增强，不替代安全规划 |

公平比较时，各多机方法必须使用相同的局部地图、传感器、轨迹规划器和动力学限制，只替换协同决策模块。RACER 的实验同样在对照中保留相同路径规划与轨迹生成，仅比较协同策略，并对每个场景重复运行五次。

## 4. 受控变量

以下参数在同一组对比中必须完全一致：

- 废墟模型、随机种子和真值 PCD；
- 探索边界与终止阈值；
- 无人机数量、初始位置和启动时间；
- 传感器视场、量程、频率和噪声；
- 地图分辨率、障碍膨胀和碰撞直径；
- 最大速度、最大加速度和局部规划器；
- 虚拟机 CPU、内存、并行线程和实时因子；
- 通信延迟、带宽和丢包模型；
- 超时时间及失败判定。

禁止在看到某种方法的结果后单独修改边界、阈值或传感器参数。若必须修正参数，应将修正前实验标为“校准实验”，重新运行全部对照方法。

## 5. 主要评价指标

### 5.1 地图完整性与几何质量

令真值占据体素集合为 \(G\)，重建占据体素集合为 \(R\)，距离阈值为 \(\tau\)。

**表面完整率/召回率**

\[
C_{\mathrm{map}}=
\frac{|\{g\in G\mid d(g,R)\leq\tau\}|}{|G|}
\]

表示真值障碍表面中有多少被重建。当前项目的 `surface_recall` 对应该指标。

**表面准确率**

\[
P_{\mathrm{map}}=
\frac{|\{r\in R\mid d(r,G)\leq\tau\}|}{|R|}
\]

表示重建点中有多少能在真值附近找到对应。当前项目的 `surface_precision` 对应该指标。

**F1**

\[
F_1=\frac{2P_{\mathrm{map}}C_{\mathrm{map}}}
{P_{\mathrm{map}}+C_{\mathrm{map}}}
\]

用于综合表达完整性与准确性。三维重建文献通常同时报告 precision、recall/completeness 和 F-score，不能只报告一个“覆盖率”。

**后续补充指标**

- 对称最近邻距离或 Chamfer Distance：表达几何偏差大小；
- 占据体素 IoU：需要同时保存可比较的占据/自由空间状态；
- 高度分层完整率：分别评价下层、上层和垂直连接区域；
- 区域遗漏率：统计死路、窄通道和二层结构是否被完整发现。

禁止使用 ICP 将重建地图强行对齐后再声称定位精度提高。若评价建图与定位联合误差，应使用原始世界坐标；ICP 对齐结果只能作为纯几何重建质量的补充。

### 5.2 探索效率

**完成时间**

\[
T_p=\min\{t\mid C(t)\geq p\}
\]

建议报告 \(T_{80}\)、\(T_{90}\) 和 \(T_{95}\)，而不仅是算法自行宣布 `finish exploration` 的时刻。多机器人探索基准将探索时间定义为达到预设目标覆盖率所需的墙钟时间。

**覆盖进度曲线与 AUC**

\[
\mathrm{AUC}=\frac{1}{T}\int_0^T C(t)\,dt
\]

覆盖率随时间曲线可以证明系统在运行过程中持续发现未知空间，而不是依赖预设路线。AUC 越高，表示在相同时间预算下获得信息越快。

**路径代价**

\[
L_{\mathrm{sum}}=\sum_{i=1}^{N}L_i,\qquad
L_{\mathrm{max}}=\max_i L_i
\]

`L_sum`反映集群总能耗代理，`L_max`反映最后一架无人机造成的任务完成瓶颈。相关基准将各机器人路程之和作为探索代价，并将路程视为电机能耗的近似。

**探索效率**

\[
\eta=\frac{\Delta V_{\mathrm{mapped}}}{L_{\mathrm{sum}}}
\]

表示集群每飞行一米新增的已知体积或有效真值体素数。

### 5.3 集群协同性

**重复覆盖率**

\[
O=\frac{\sum_i |V_i|-|\bigcup_i V_i|}
{|\bigcup_i V_i|}
\]

其中 \(V_i\) 为第 \(i\) 架无人机独立观测到的体素集合。该指标直接回答多架无人机是否在重复工作。

**负载不均衡**

\[
B_L=\frac{\mathrm{std}(L_1,\ldots,L_N)}
{\mathrm{mean}(L_1,\ldots,L_N)}
\]

还应对每机新增体素数、任务数和有效飞行时间计算类似变异系数。

**加速比与并行效率**

\[
S_N=\frac{T_1}{T_N},\qquad
E_N=\frac{S_N}{N}
\]

三机达到同等覆盖率的时间若仅缩短为单机的二分之一，则加速比为2，并行效率约为0.67，不能简单宣称“三倍提升”。

**协调事件**

- Frontier 分配与重分配次数；
- 多机竞争同一任务的冲突次数；
- 分配振荡次数；
- 通信消息数、字节数、延迟和丢包率。

### 5.4 安全性与可执行性

- 任务成功率；
- 碰撞次数；
- 最小机间距离；
- 最小障碍间距；
- 碰撞重规划次数；
- 规划失败次数；
- 超时和进程异常退出次数。

不能仅用“碰撞重规划日志为零”代替真实碰撞检查。仿真器碰撞状态、无人机间最小距离和轨迹可行性需要分别记录。

### 5.5 计算开销

- Frontier 检测时间；
- 任务分配时间；
- 全局/局部规划时间；
- 轨迹生成时间；
- 单次决策平均值、标准差和 P95；
- CPU、内存和仿真实时因子。

FUEL 和 RACER 都报告主要规划模块的计算时间。只有平均计算时间低于决策周期且 P95 不发生持续超时，才能声称具备实时性。

## 6. 实验分层

### E0：环境有效性

- 验证通道满足碰撞直径约束；
- 验证环路、岔路、死路、高差和垂直连接；
- 验证固定种子可复现，未知种子不会产生不可通行地图。

### E1：单机参数校准

- 比较初始统一高度边界与任务有效高度边界；
- 仅用于确定正式协议；
- 修正前后的实验不能混入同一统计表。

第一次 `0.35-7.65 m` 的成功运行属于 E1。它证明系统能够自主运行并保存地图，但不是最终单机基线的重复样本。

### E2：正式单机基线

- `base`、`medium`、`complex`分别先运行3次作为工程验收；
- 最终论文使用固定且未见的随机种子；
- 记录地图质量、覆盖曲线、时间、路径、安全和计算开销。

### E3：三机对照

在完全相同的随机种子上运行 B2、B3、B4 和 M1。单机 B1 用于计算加速比，多机方法之间的比较才用于证明协同算法优势。

### E4：消融实验

依次移除信息增益、重复惩罚、负载均衡和通信约束项，确认性能提升来自哪个模块。

### E5：鲁棒性

- 未见随机废墟；
- 10%、30%、50%通信丢包；
- 通信延迟；
- 定位漂移；
- 单机中途退出。

强化学习若加入，位于 E5 之后，作为高层效用预测或权重优化，不直接替代安全轨迹规划。

## 7. 重复次数与统计

- 工程调试：每条件1次，不用于论文结论；
- 固定场景验收：每条件至少3次；
- 正式方法比较：建议每种方法使用相同的至少10个随机种子；
- 通信或故障实验：每个扰动等级至少5次。

同一随机种子在所有方法间配对。每项核心指标报告：

- 成功次数/总次数；
- 均值 ± 标准差；
- 中位数和四分位距；
- 95%置信区间；
- 相对改进百分比。

对配对种子优先使用配对统计检验；不满足正态性时使用 Wilcoxon 符号秩检验，并报告效应量。超时和失败不能删除，应按照预先声明的失败规则计入。

代表性地图和轨迹图选择最接近该方法中位数的运行，不能选择最好的一次。

## 9. 当前实现状态与缺口

已经实现：

- FUEL 自主结束检测；
- 运行时间和总路径长度；
- 规划失败和碰撞重规划日志；
- 最终在线占据 PCD；
- 表面 recall、precision、F1；
- 结果哈希、CSV和论文三联图归档。

下一步必须实现：

1. 保存带时间戳的无人机轨迹；
2. 记录体素首次发现时间，离线生成真实覆盖率—时间曲线；
3. 记录规划耗时平均值和 P95；
4. 记录仿真实时因子和资源使用；
5. 三机阶段记录每机新增体素、重叠率、负载和通信开销；
6. 在正式运行前冻结指标定义、边界和失败规则。

## 10. 主要文献依据

1. Zhou et al., FUEL: Fast UAV Exploration using Incremental Frontier Structure and Hierarchical Planning. FUEL使用层次化Frontier规划，并通过探索时间、路径和计算效率进行比较：<https://arxiv.org/abs/2010.11561>
2. Zhou et al., RACER: Rapid Collaborative Exploration with a Decentralized Multi-UAV System. RACER采用协同模块消融、相同底层规划、公平对照、每场景五次重复，并评价探索进度、时间、路径和计算开销：<https://arxiv.org/abs/2209.08533>
3. Yan et al., Metrics for Performance Benchmarking of Multi-Robot Exploration. 该文系统定义探索时间、总航程、探索效率、地图完整性和地图质量：<https://yzrobot.github.io/publications/yz15iros.pdf>
4. Faigl et al., Decentralized multi-robot exploration under low-bandwidth communications. 该文使用多环境、多次重复、时间、最长/总航程、单机覆盖和重叠分析，并报告均值和标准差：<https://link.springer.com/article/10.1007/s10514-025-10234-3>
5. 3D reconstruction evaluation literature commonly defines completeness as ground-truth points reconstructed within a distance threshold, combines precision and recall using F-score, and reports the threshold explicitly：<https://www.mdpi.com/2571-9408/6/3/143>
