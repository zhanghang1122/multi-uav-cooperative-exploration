# 小论文问题定义与算法接口

## 1. 任务定义

环境为有限但先验未知的三维废墟空间。单机或三机从入口附近的已验证安全
位置起飞，只能访问当前传感器观测和由观测在线更新的地图。仿真器内部可
加载完整 PCD 作为传感器渲染真值，但规划节点不得订阅或读取该真值。

探索完成的含义是：在给定探索边界内不再存在满足可见性、尺寸和可达性
条件的有效 Frontier，或者达到实验统一规定的覆盖率阈值。它不是到达一个
预先给定的终点坐标。

## 2. Frontier 的严格含义

三维占据地图包含三种体素状态：

- `occupied`：被观测为障碍；
- `free`：传感器射线验证为可通行空间；
- `unknown`：尚未获得充分观测。

Frontier 是与未知体素相邻的已知自由体素集合。算法对相邻 Frontier 体素
聚类，并在聚类周围生成满足安全距离和可见性的候选视点。因此“区域”不是
人工提前划分的房间，而是地图在线增长后从几何结构中产生的临时任务。

## 3. 单机基线接口

| 类别 | 内容 |
|---|---|
| 观测 | 当前位姿、局部深度/点云 |
| 内部状态 | 在线三维占据地图、Frontier Information Structure |
| 决策 | Frontier 访问次序、局部候选视点 |
| 规划输出 | 动力学可行的 B 样条轨迹 |
| 控制输出 | 位置/速度/加速度指令 |
| 终止 | FUEL 状态机进入 `FINISH` |

FUEL 的完整 PCD 只连接局部传感器渲染器。规划器接收的是当前传感器输出，
而不是 PCD 文件或预制 OctoMap。

## 4. 后续三机问题接口

每架无人机 `i` 在时刻 `t` 具备：

- 位姿与速度 `x_i(t)`；
- 当前局部/共享占据地图 `M_i(t)`；
- 在线 Frontier 集合 `F_i(t)`；
- 动态拓扑摘要 `G_i(t)`；
- 邻机状态或延迟通信摘要 `C_i(t)`。

协调层输出无人机到 Frontier/拓扑分支的一对一或部分分配。底层仍由经过
碰撞检查的局部规划器生成轨迹。协调层不得直接输出电机转速。

候选分配代价至少包含：

```text
J(i, f) =
  w_d * travel_cost(i, f)
  - w_g * information_gain(f)
  + w_r * collision_or_clearance_risk(i, f)
  + w_o * overlap_with_other_uavs(f)
  + w_c * communication_risk(i, f)
```

第一版使用可解释的固定权重和确定性分配；强化学习若加入，只优化上述
高层决策，不移除安全约束。

## 5. 基线与消融

| 编号 | 方法 | 要回答的问题 |
|---|---|---|
| B1 | FUEL 单机 | 场景是否可被自主探索完成 |
| B2 | 三机独立 FUEL，无任务协调 | 多加无人机是否会产生重复探索 |
| B3 | 最近 Frontier 贪心分配 | 简单显式协调能提高多少 |
| M1 | 本文动态拓扑分配 | 拓扑代价和重分配是否有效 |
| A1 | M1 去掉拓扑代价 | 动态拓扑信息的贡献 |
| A2 | M1 去掉重叠惩罚 | 去重复机制的贡献 |
| A3 | M1 加入通信延迟/丢包 | 受限通信鲁棒性 |
| O1 | 可选学习权重 | 学习策略是否在未见地图上继续提升 |

## 6. 主要评价指标

- 达到 90% 和 95% 覆盖率的时间；
- 探索完成时间和成功率；
- 三机总路径长度与最大单机路径长度；
- 重复观测体积比例；
- 最小机间距离和碰撞次数；
- Frontier 分配次数、重分配次数和任务振荡次数；
- 通信字节数、消息频率、延迟和丢包条件；
- 规划耗时、CPU 使用和 Gazebo/MARSIM 实时因子。

所有比较必须使用相同地图、随机种子、起始位姿、传感器模型、动力学限制和
终止条件。训练地图与未见测试地图必须分开。
