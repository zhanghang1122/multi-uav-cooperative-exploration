# P0 首次单机探索试验复盘

## 试验定位

本次 `Ruins-Urban-01_base` 的 FUEL 运行是工程连通性和自主性验证，不是论文中的单机对比样本。规划器只接收入口初始位姿、矩形探索边界及在线局部传感器数据；没有输入路线、航点、目标坐标、障碍分区或先验占据地图。

已验证事实：FUEL 接收到启动信号后在线生成前沿视点和轨迹，在线占据地图增长，最终记录了 `finish exploration` 并导出 PCD。因此，它证明了“未知环境下单机自主探索链路可运行”，但没有证明“当前配置的地图重建质量已达到论文比较要求”。

## 首次试验的关键缺口

1. **搜索高度设置不正确。** 初次运行允许 `0.35–7.65 m`，而 base 场景无上层通行任务；模型最高点约 `3.877 m`。这会使无人机清扫大量无效未知体积，增加路径与完成时间。
2. **覆盖率口径不足。** 只对比最终在线 PCD 与完整仿真表面，无法区分可由飞行器看见的表面、被遮挡的表面和安全半径不可接近的表面。
3. **缺少过程证据。** 该首次记录未同时保存覆盖率随时间变化、规划耗时、资源占用、事件日志和原始规划日志，不能判断是否存在提前终止或计算退化。
4. **没有重复性。** 一次成功或一次覆盖偏低均不能代表 FUEL 的稳定性能。
5. **图像不是论文图。** RViz/PCD Viewer 的截图只能用于调试；论文需要固定相机、真值-重建-差异图、覆盖曲线和跨重复统计表。

## 已冻结的修正

- `base` 搜索高度固定为 `0.35–2.65 m`；`medium` 与 `complex` 固定为 `0.35–5.00 m`。这只限制合法搜索体积，不给出任何内部路线。
- 后续运行统一采用证据记录器，保存轨迹、首次观测体素、覆盖率时间序列、规划耗时、系统资源、事件与最终在线 PCD。
- 后处理同时保留全表面指标，并将新增“轨迹条件下的可观测表面审计”，避免把不可见表面误写为规划失败。
- 本地 `results/` 目录仅存实验原始数据，不随源码提交，也不会在更新源码时被覆盖。
